# project-daily-summary

按项目汇总今天的工作。使用全局 Claude 会话记录作为主要证据来源，然后用 git 提交和未提交变更丰富。优先关注计划和最终结果，而非过程叙述。

## 核心规则

不要生成按时间顺序的流水账。
不要总结推理噪音。
始终按**项目**汇总，然后按**主要工作流**汇总。

## 数据来源优先级

1. `~/.claude/sessions/` 下的会话记录（如存在）
2. `~/.claude/history.jsonl`
3. `<project>/.specstory/history/` 如果存在
4. `git log`、`git status --short`、`git diff --stat`

## 重要环境假设

会话记录主要存储在：
```text
~/.claude/projects/<project-hash>/
```

通过 `cwd` 字段将会话映射回项目：
- 尝试：`git -C <cwd> rev-parse --show-toplevel`
- 如果失败，回退到 `cwd` 作为项目键

## 范围

### 默认范围

总结出现在今天会话中的**所有项目**。

### 如果用户提供了文件夹

只总结那些文件夹或仓库。

## 工作流

### 步骤 1：确定今天的本地日期

使用本地机器日期，不是 UTC。

### 步骤 2：按项目分组

对于每个会话：

1. 尝试：
   ```bash
   git -C <cwd> rev-parse --show-toplevel
   ```
2. 如果失败，使用 `cwd` 作为项目键。

每个项目输出一个部分，不是每个原始会话一个部分。

### 步骤 3：正确处理子代理

许多会话可能是派生的子代理。不要将每个子会话列为单独的用户面向项目。

策略：
- 主会话是主要叙述单元
- 子代理会话仅作为支持证据
- 如果同一天存在父会话，将子代理合并到父工作流
- 如果父会话缺失，将子代理作为孤立证据合并到最近匹配的项目工作流

### 步骤 4：添加 git 证据

对于每个项目，运行：

```bash
git -C <repo> log --since="YYYY-MM-DD 00:00" --until="YYYY-MM-DD 23:59" --pretty=format:"%h %s"
git -C <repo> status --short
git -C <repo> diff --stat
```

产出：
- 今日 commits
- 当前未提交改动

### 步骤 5：忽略过程噪音

默认忽略：
- 推理项
- token 计数
- 大多数系统和开发者提示内容
- 大多数中间工具交互
- 重复的子代理脚手架

仅保留：
- 用户目标
- 提取的计划
- 最终结果
- 变更的文件
- 运行的测试
- 风险或阻塞

### 步骤 6：将会话合并为主要工作流

在每个项目中，将多个会话合并为几个主要工作流。

使用这些信号：
- 相同分支或 worktree
- 相同或相似的用户目标
- 重叠的变更文件
- 相同计划文件
- 相同功能、bug、审查或 skill 话题

目标每个项目 **1 到 5 个工作流**，不是几十个小条目。

## 输出格式

```md
# Claude Project Daily Summary
日期：YYYY-MM-DD

## 总览
- 项目数：
- 会话数：
- 主要推进：
- 今日仍未收尾：

## 项目：<repo-or-folder>
- 分支 / 仓库：
- 今日目标：
- 今日计划提炼：
- 今日完成事项：
- 今日 commits：
- 当前未提交改动：
- 风险 / 未完成项：
- 建议下一步：

## 项目：<repo-or-folder>
...

## 跨项目总结
- 今天最重要的推进
- 重复出现的问题
- 明天最值得先做的 1-3 件事

## 附录：Closeout / 未收口 Worktree / 分支收口状态（可选）
- 仅当用户额外要求当天所有 repo 的 closeout / worktree / 分支收口状态时添加
- 可附 `/worktree-closeout` 的摘要、优先级、artifact 路径
```

## 写作规则

- 使用中文写作。
- 先按项目分组。
- 以结果为先，不以过程为先。
- 清晰区分：
  - 会话计划
  - 已完成事项
  - 已提交内容
  - 未提交改动
- 如果证据缺失，明确说明。
- 如果项目没有 git 仓库，说明提交和未提交部分不可用。

## 默认保存位置

使用此策略：
1. 如果当前项目的 `CLAUDE.md` 定义了日报输出目录，遵循它
2. 否则，第一次询问用户输出目录
3. 使用文件名模式：`YYYY-MM-DD-project-daily.md`
