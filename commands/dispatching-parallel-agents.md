# Dispatching Parallel Agents

## 概述

你将任务委托给具有隔离上下文的专门 agents。通过精心制作他们的指令和上下文，确保他们保持专注并在任务中成功。他们不应该继承你的会话上下文或历史——你构建他们确切需要的内容。这也为协调工作保留了你自己的上下文。

当有多个不相关的失败（不同测试文件、不同子系统、不同 bug），顺序调查会浪费时间。每个调查都是独立的，可以并行进行。

**核心原则：** 每个独立问题域一个 agent。让他们并发工作。

## 使用时机

**使用当：**
- 3+ 个测试文件以不同根因失败
- 多个子系统独立损坏
- 每个问题可以在没有其他问题上下文的情况下理解
- 问题之间无共享状态

**不使用当：**
- 失败相关（修复一个可能修复其他）
- 需要理解完整系统状态
- Agents 会相互干扰

## 模式

### 1. 识别独立域

按损坏的内容分组失败：
- 文件 A 测试：工具批准流程
- 文件 B 测试：批次完成行为
- 文件 C 测试：中止功能

每个域都是独立的——修复工具批准不影响中止测试。

### 2. 创建专注的 Agent 任务

每个 agent 获得：
- **具体范围：** 一个测试文件或子系统
- **明确目标：** 使这些测试通过
- **约束：** 不要更改其他代码
- **预期输出：** 你发现和修复了什么的摘要

### 3. 并行派发

使用 Claude Code 的 Agent 工具，在同一条消息中发出多个 Agent 调用：

```
Agent({
  prompt: "修复 src/agents/agent-tool-abort.test.ts 中的 3 个失败测试...",
  run_in_background: true
})

Agent({
  prompt: "修复 src/batch/batch-completion-behavior.test.ts 中的失败测试...",
  run_in_background: true
})

Agent({
  prompt: "修复 src/tool/tool-approval-race-conditions.test.ts 中的失败测试...",
  run_in_background: true
})
```

### 4. 审查并整合

当 agents 返回时：
- 读取每个摘要
- 验证修复不冲突
- 运行完整测试套件
- 整合所有变更

## Agent Prompt 结构

好的 agent prompts 是：
1. **专注** — 一个清晰的问题域
2. **自包含** — 理解问题所需的所有上下文
3. **关于输出的具体** — Agent 应该返回什么？

```markdown
修复 src/agents/agent-tool-abort.test.ts 中的 3 个失败测试：

1. "should abort tool with partial output capture" — 消息中期望 'interrupted at'
2. "should handle mixed completed and aborted tools" — fast tool 被中止而不是完成
3. "should properly track pendingToolCount" — 期望 3 个结果但得到 0

这些是时序/竞态条件问题。你的任务：

1. 读取测试文件，理解每个测试验证什么
2. 识别根因——时序问题还是实际 bug？
3. 修复方式：
   - 用基于事件的等待替换任意超时
   - 如果在中止实现中发现 bug 则修复
   - 如果测试行为变更则调整测试期望

不要只是增加超时——找到真正的问题。

返回：你发现了什么和你修复了什么的摘要。
```

## 常见错误

**❌ 太宽泛：** "修复所有测试" — agent 迷失
**✅ 具体：** "修复 agent-tool-abort.test.ts" — 专注范围

**❌ 无上下文：** "修复竞态条件" — agent 不知道在哪里
**✅ 上下文：** 粘贴错误消息和测试名称

**❌ 无约束：** Agent 可能重构所有内容
**✅ 约束：** "不要更改生产代码"或"只修复测试"

**❌ 模糊输出：** "修复它" — 你不知道什么变了
**✅ 具体：** "返回根因和变更的摘要"

## 何时不使用

**相关失败：** 修复一个可能修复其他——先一起调查
**需要完整上下文：** 理解需要看到整个系统
**探索性调试：** 你还不知道什么损坏了
**共享状态：** Agents 会相互干扰（编辑同一文件、使用同一资源）

## 验证

Agents 返回后：
1. **审查每个摘要** — 理解什么变了
2. **检查冲突** — Agents 是否编辑了相同代码？
3. **运行完整套件** — 验证所有修复一起有效
4. **抽查** — Agents 可能犯系统性错误

## 并行化的好处

1. **并行化** — 多个调查同时发生
2. **专注** — 每个 agent 有窄范围，要追踪的上下文更少
3. **独立** — Agents 不相互干扰
4. **速度** — 1 个问题的时间内解决 3 个问题
